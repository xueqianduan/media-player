# ReelBox 文件传输模块功能需求分析

文档版本：1.0  
编制日期：2026 年 11 月 11 日  
适用范围：Android 文件传输首版  
使用对象：产品设计、客户端开发、测试

ReelBox 新增独立的文件传输模块，支持用户在手机之间发送和接收已授权访问的本地文件。首版采用无账号的局域网或热点传输，以接收方展示二维码、发送方扫码建立连接为唯一连接入口。视频页面的分享功能复用同一模块，并自动带入用户选中的视频。

本需求以最终确认的简化交互为基准：接收准备集中在一个页面状态中；发送端选择文件后直接进入扫码；相机权限由系统弹窗按需申请。早期设计中的连接方式选择、附近设备列表、手动配对码和独立授权说明页面不纳入首版。

## 1 产品定位与功能范围

### 1.1 入口与职责

应用底部导航调整为“本地、网络、传输、我的”。“传输”替换“磁力”成为一级入口，磁力功能的位置留待后续版本规划。

| 入口 | 主要职责 | 与传输模块的关系 |
| --- | --- | --- |
| 本地 | 浏览文件夹、管理和播放本机视频 | 单个或多选视频的分享动作调用发送流程 |
| 网络 | 网络视频和直播 | 首版不将直播流作为文件传输，也不自动录制直播 |
| 传输 | 发送文件、接收文件、查看传输记录 | 独立一级功能入口 |
| 我的 | 收藏、分类、播放列表和设置 | 可提供接收保存目录等设置入口 |

### 1.2 首版包含的能力

- 在已具备互通网络的 Android 设备之间，一发一收地传输单个或多个文件。
- 选择视频、应用安装包、文档、图片、音频和其他文件。
- 视频、图片、音频支持全部文件和按文件夹两种浏览方式。
- 跨文件类型、跨文件夹保留选择，查看已选文件并逐个移除或清空。
- 扫码建立临时传输会话；发送端连接成功后开始发送。
- 显示文件队列、传输进度、暂停、继续、取消、完成和失败状态。
- 查看最近记录及按方向、文件类型筛选的完整历史。
- 按操作和系统版本检查所需权限，不在模块首页集中索取权限。

### 1.3 首版边界

首版以安装 ReelBox 的 Android 设备之间传输为验收基线。接收方主动进入接收状态并展示有效二维码，即表示允许当前配对会话接收文件；连接完成后展示传输详情，不另加一个接收确认页面。

首版不包含账号、联系人、异地远程分享、云端文件存储、手动配对码、附近设备选择列表、一对多发送、电脑浏览器接收和 iOS 适配。网络断开、进程退出后跨会话恢复大文件的断点续传列入后续版本，不在首版界面承诺。

“应用”指可读取的应用安装包，例如 APK。首版不承诺搬迁已安装应用的数据、不自动安装接收的 APK，也不承诺将拆分安装包合并为单一可安装文件。已安装应用导出能力需要单独确定实现范围。

“任何文件”指用户已授权、系统允许应用读取的文件。其他应用的私有数据、系统受保护目录不属于可任意访问的范围。

## 2 用户场景与主流程

### 2.1 从传输首页发送

1. 用户点击“发送文件”。
2. 进入文件选择页，按类型浏览文件，或进入文件夹查找。
3. 选中一个或多个文件，可展开已选清单检查名称和大小。
4. 点击与已选数量同一行的“下一步”。
5. 直接进入扫码发送页；缺少相机权限时调用系统授权弹窗。
6. 扫描接收方二维码，完成网络连接、会话及文件清单校验。
7. 校验通过后自动进入传输详情并开始发送。

选择完文件后不出现“选择连接方式”“选择附近设备”或“输入配对码”等中间步骤。

### 2.2 从视频分享入口发送

用户在播放器、单个视频菜单或视频多选操作栏点击“分享”，进入同一发送流程，并自动选中这些视频。文件选择页展示正确的已选数量，允许继续添加其他文件或移除预选项，不要求用户重新查找原视频。

### 2.3 接收文件

1. 用户点击“接收文件”。
2. 检查当前传输方案需要的权限、网络和设备开关。
3. 条件齐全时直接显示接收二维码；有缺失条件时，在同一接收页面显示统一准备状态。
4. 用户逐项处理缺失条件，应用返回前台后重新检查。
5. 准备完成后自动切换为二维码等待状态，不要求再次点击“下一步”。
6. 发送方扫码并完成连接后，接收端自动进入传输详情。
7. 接收完成后可查看已收文件或返回传输首页。

显示二维码不使用摄像头，因此接收端不因展示二维码而申请相机权限。

### 2.4 页面流转

```
    A[传输首页] --> B[选择文件]
    B --> C[扫码发送]
    C --> D[连接与会话校验]
    A --> E[接收文件]
    E --> F{接收条件是否齐全}
    F -->|否| G[同页显示缺失准备项]
    G --> F
    F -->|是| H[同页显示接收二维码]
    H --> D
    D --> I[传输详情]
    I --> J[完成或失败状态]
    A --> K[完整传输记录]
    J --> K
```

## 3 页面结构与交互

页面按用户任务划分。授权、加载、完成和失败优先作为现有页面中的状态，不继续拆分成独立路由。

| 页面 | 页面编号 | 主要内容 | 进入方式 |
| --- | --- | --- | --- |
| 传输首页 | P01 | 发送、接收、最近记录、查看全部 | 底部“传输”导航 |
| 选择文件 | P02 | 类型分类、全部或文件夹、文件多选、已选抽屉 | 发送或视频分享 |
| 接收文件 | P03 | 缺失条件准备状态、二维码等待状态 | 点击接收 |
| 扫码发送 | P04 | 扫码框、相机状态、连接结果 | 文件选择页下一步 |
| 传输详情 | P05 | 文件队列、进度、暂停和取消、完成或失败 | 配对连接成功 |
| 传输记录 | P06 | 方向筛选、类型筛选、历史记录 | 首页查看全部 |

### 3.1 传输首页

首页标题为“文件传输”，不显示返回箭头，底部显示“本地、网络、传输、我的”且高亮“传输”。主内容只包含两个主要操作“发送文件”“接收文件”和最近传输记录。

最近记录展示少量条目，包含名称或任务摘要、方向、状态；进行中任务展示进度并可进入详情。“查看全部”进入 P06。没有记录时显示空状态，不使用虚构记录、设备或速度作为真实数据。

首页不放置局域网传输说明卡、文件类型快捷选择、完整历史筛选、永久授权清单或接收目录设置卡。

### 3.2 文件选择页

类型分类为“视频、应用、文档、图片、音频、其他”。视频、图片、音频分类下提供“全部文件”和“文件夹”浏览切换。文件行至少显示可识别的名称、大小和选中状态；视频、图片可以使用缩略图，音频和文档使用文件类型图标。

文件夹模式展示文件夹名称、该类型文件数量和进入箭头；可以补充该文件夹的已选数量。进入文件夹后展示该文件夹中的对应文件，返回上级不会丢失选择。同名文件夹应有能够区分来源的位置说明。

“全选”的范围必须明确：全部文件模式为当前类型的全部可选结果，进入文件夹后为当前文件夹的对应文件。文件夹列表层隐藏全选，避免将“选择文件夹”和“选择其中所有文件”混为一谈。取消全选只移除当前范围的选择，不清除其他类型或文件夹中的已选项。

无文件、无访问权限、加载中、文件已失效分别显示对应状态。权限不足时允许申请所需权限，或使用系统文件选择器补充文件，不使用一个通用“暂无文件”掩盖所有原因。

### 3.3 底部操作栏与已选清单

底部固定操作栏采用一行横向布局：左侧为可点击的“已选 N 项”和展开指示，右侧为“下一步”。按钮和数量不得改为上下堆叠。

点击已选数量，在当前页面上方展开底部清单。清单显示每个文件的名称、大小和右侧小“×”移除按钮，标题区域提供“清除全部”。清单不另设重复的下一步按钮，底部原有操作栏仍然可见。

- 单项移除立即更新文件行勾选、已选数量、文件夹已选数量和清单。
- 清除全部作用于所有类型及文件夹中的全局选择；清空后显示零项状态。
- 已选数量为零时禁用下一步；当前分类没有文件但其他分类已有选择时，下一步仍可用。
- 同一个文件不能因切换分类或浏览方式而重复加入；去重依据文件身份或授权 URI，不能只依据文件名。
- 同名但内容或位置不同的文件可以同时选择，应提供来源信息帮助区分。

### 3.4 接收页面

接收准备和二维码等待是 P03 的两个状态。准备状态只显示当前缺失的必要条件，每项包含名称、原因或当前状态，以及“允许”“开启”或“去设置”等准确动作。

已经满足的条件不要求用户再次处理。所有条件满足后自动显示本机设备名称和临时接收二维码，并显示“等待连接”。接收页仅提供扫码接收，不展示配对码和附近设备选择入口。

点击取消接收或退出等待页后，二维码对应的会话立即失效，停止等待新的连接。应用只释放本次自行创建的连接资源，不擅自关闭用户原先开启的 Wi-Fi、蓝牙或热点。

### 3.5 扫码发送页

页面包含返回入口、扫码区域、简短操作说明和已选文件数量。已有相机权限时直接启动扫码；首次缺少权限时，使用系统授权弹窗，不增加独立相机说明页面。

扫码成功后暂停重复识别，校验二维码所属协议、有效期、网络可达性和会话状态。连接成功后自动发送已选文件。连接失败时在当前页面提示原因并允许重新扫码，返回文件选择页时保留选择。

相机权限被拒绝时，在当前页面提示并提供重新授权或返回选择页的动作；系统不再允许弹出授权时提供去设置入口。不得连续自动重复弹窗。

## 4 功能需求清单

P0 为首版必需，P1 为首版目标能力。P1 功能若未完成，应调整界面，不得保留可点击但无实际效果的占位按钮。

| 编号 | 功能 | 优先级 | 可观察的结果 |
| --- | --- | --- | --- |
| FR01 | 导航和独立入口 | P0 | 传输替换磁力，首页可直接发送和接收 |
| FR02 | 视频分享复用 | P0 | 单个或多选视频自动带入统一发送清单 |
| FR03 | 多类型文件选择 | P0 | 六类入口能够提供实际可访问的文件 |
| FR04 | 媒体文件夹浏览 | P0 | 视频、图片、音频可切换全部和文件夹 |
| FR05 | 全局多选和去重 | P0 | 跨类型、跨文件夹保留选择且同文件不重复 |
| FR06 | 已选清单管理 | P0 | 查看名称大小、单项移除、清除全部实时生效 |
| FR07 | 接收准备检查 | P0 | 缺失条件同页处理，满足后自动展示二维码 |
| FR08 | 扫码连接 | P0 | 发送端下一步直达扫码，连接成功自动发送 |
| FR09 | 多文件传输队列 | P0 | 一发一收会话中按队列传输所选文件 |
| FR10 | 进度与结果反馈 | P0 | 展示真实字节进度、文件状态和任务结果 |
| FR11 | 取消和失败重试 | P0 | 可终止传输，失败可重新连接并重试 |
| FR12 | 暂停与继续 | P1 | 在仍有效的本次会话中暂停并继续传输 |
| FR13 | 文件保存与校验 | P0 | 完整文件成功保存、内容校验后才标记完成 |
| FR14 | 历史与分类筛选 | P0 | 查看全部后可按类型和方向组合筛选 |
| FR15 | 资源释放 | P0 | 退出或取消后关闭本次监听、连接和读写资源 |

### 4.1 发送清单与任务建立

进入发送流程后先建立可编辑的文件清单。点击下一步时，再检查文件是否存在、读取授权是否有效、大小是否可取得。某个文件失效时，应指出该文件并允许移除或重新选择，不能无提示地发送其余文件。

连接建立后对本次清单生成快照。正在传输的任务不随其他页面后续勾选操作变化。首版同一设备只允许一个活动传输任务，新的任务需要等待、取消现有任务或在现有任务结束后开始。

### 4.2 传输进度与结果

传输详情至少包含对方设备名称、发送或接收方向、总进度、已传字节数、总大小、当前文件和文件队列。速度为实际计算结果，不使用设计图中的示例速度作为保证。

总进度按全部文件的字节数计算，不能按文件数量平均计算。单个文件仅在接收端写入完成并通过内容校验后标记完成；全部文件完成并收到对端确认后，任务才标记完成。

暂停后停止推进文件数据，保留本次有效会话及已确认的进度。继续操作恢复当前任务。进程被系统终止、网络断开或会话失效后的恢复属于重新连接和重试，不承诺首版跨会话断点续传。

取消操作同时通知对端，停止剩余队列并关闭读写。未完成的临时文件不得出现在接收目录中冒充完整文件；已完成文件保持可用。用户取消不会删除发送方原文件。

### 4.3 接收保存规则

默认保存到用户可见且应用有写入权限的 ReelBox 接收目录，页面显示友好位置名称。用户自定义目录时通过系统授权完成选择，不假定应用拥有任意目录访问权。

同名文件默认追加序号等方式生成新名称，不能静默覆盖已有文件。写入时使用临时文件，完成和校验成功后再转为正式文件。保存空间不足、写入失败、目录授权被撤回时，显示明确原因并停止受影响的传输。

接收 APK、文档和压缩包仅完成保存，不自动安装、执行或解压。视频可以从接收结果页交给播放器打开；其他类型交给支持该类型的系统应用。

## 5 权限与设备状态要求

权限不足和设备未开启是不同状态：权限动作使用“允许”或“去设置”，Wi-Fi、蓝牙等开关使用“开启”或“去连接”。授权成功不等于设备开关已经打开，返回应用后需要重新检查实际状态。

| 能力 | 申请时机 | 处理要求 |
| --- | --- | --- |
| 自建视频 图片 音频列表 | 用户进入对应文件分类，需要读取时 | 按系统版本申请当前类型的媒体访问权限 |
| 系统文件选择器 | 用户选择具体文件或目录时 | 使用用户授予的 URI 权限，不默认索取所有文件访问权 |
| 相机扫码 | 发送端进入扫码流程时 | 已允许直接使用；缺少时调用系统弹窗；接收显示二维码不申请 |
| 局域网通信 | 建立本地连接或准备接收时 | 声明基础网络权限；按系统版本及目标 SDK 适配局域网运行时授权 |
| 附近 Wi-Fi 或本地热点 API | 底层方案实际调用这些 API 时 | 在统一接收准备状态中处理对应的必要权限 |
| 蓝牙辅助连接 | 底层方案确实使用蓝牙时 | 按操作申请扫描 连接 广播所需权限，并单独检查蓝牙开关 |

默认传输通道为已互通的局域网或热点。若实际实现仅使用局域网扫码，不能因为蓝牙关闭就禁止接收，也不能强制申请未使用的蓝牙权限。若选型采用蓝牙辅助连接，则只在需要且缺失时展示对应项目。

Android 17 且目标 SDK 为 37 或更高时，直接局域网访问需要适配 ACCESS_LOCAL_NETWORK。目标 SDK 较低时不能机械地照搬该权限申请。Wi-Fi Direct、本地热点和蓝牙操作还需分别依据调用的 API 处理权限，不能用一个固定权限清单覆盖所有系统版本。

接收准备页与发送扫码页允许调用系统原生授权弹窗、设备开启确认或设置面板，但不再增加多层自定义权限说明路由。拒绝某项权限后，用户仍可返回首页查看历史或调整文件选择。

## 6 异常与边界场景

| 场景 | 期望行为 |
| --- | --- |
| 没有已选文件 | 下一步禁用，允许继续选择 |
| 文件失效或读取授权失效 | 指出受影响文件，允许移除或重新选择 |
| 相机拒绝授权或不可用 | 扫码页提示原因，保留清单，允许返回或去设置 |
| 接收条件未满足 | 在同一接收页只列出缺失条件 |
| 非本应用协议二维码 | 提示二维码不支持，不建立传输连接 |
| 二维码过期或接收方已退出 | 提示接收码失效，允许重新扫描新二维码 |
| 网络不互通或路由器隔离设备 | 在现有页面提示连接失败，指导连接同一可互通网络或热点 |
| 重复识别同一二维码 | 同一次扫码只发起一个连接和一个任务 |
| 接收方正在处理其他任务 | 返回忙碌状态，发送端保留清单 |
| 网络中断或对方取消 | 双方更新任务状态，不停留在无限加载 |
| 空间不足或写入失败 | 显示具体原因，停止受影响任务并保留已完成结果 |
| 出现同名接收文件 | 自动生成不冲突的新名称，原文件不被覆盖 |
| 内容校验不通过 | 文件标记失败，不当作完整文件开放使用 |
| 暂停后会话失效 | 提示需要重新连接，不把重新发送冒充无缝继续 |
| 历史对应的文件已被删除 | 保留历史结果，打开时提示文件已不存在 |
| 接收期间退出页面 | 等待状态立即取消；进行中任务先提示是否取消，不静默终止 |
| 返回系统桌面或进程被回收 | 不承诺后台持续传输；恢复时重新校验任务，不能一直显示传输中 |

连接和握手必须有超时上限，超时后终止本轮连接。具体超时数值作为可配置技术参数确定，不在界面无限等待，也不无限自动重试。重试仍以扫码建立新会话为入口，不恢复被首版移除的连接方式选择页。

## 7 任务状态与生命周期

| 状态 | 用户看到的结果 | 主要允许操作 |
| --- | --- | --- |
| 待选择 | 文件列表和已选数量 | 选择 移除 清空 |
| 待扫码 | 扫码框或相机授权状态 | 扫码 返回 |
| 接收准备中 | 当前缺失条件 | 允许 开启 去设置 取消 |
| 等待连接 | 有效接收二维码 | 取消接收 |
| 连接中 | 正在连接的短时状态 | 取消 |
| 传输中 | 字节进度和文件队列 | 暂停 取消 查看详情 |
| 已暂停 | 保留的会话和进度 | 继续 取消 |
| 已完成 | 文件结果和保存位置 | 查看文件 返回 |
| 失败或中断 | 明确原因和已完成情况 | 重新连接重试 返回 |
| 已取消 | 已终止的任务状态 | 返回 查看记录 |

用户重复点击下一步、扫码回调重复到达、页面重建或快速退出进入，都不能创建重复任务。异步回调需要绑定本次会话，旧会话关闭后不能继续更新新页面或重新开启连接。

完成、取消、失败和退出时，应释放本次创建的网络监听、Socket、扫码相机、文件流和临时资源。只有这些资源确实释放后，才允许建立新的同类任务，避免重复进入造成资源堆积。

## 8 历史记录与数据要求

首页只展示最近记录。“查看全部”进入完整历史页，同时支持方向筛选“全部、发送、接收”和文件类型筛选“全部、视频、应用、文档、图片、音频、其他”，两个条件组合生效。

多类型批量任务在历史中保留任务与文件的对应关系。按文件类型筛选时，应能看到匹配的文件级记录，而不是让整个混合任务只归入一个类型。进行中、成功、失败和取消需要有可区分状态。

| 数据对象 | 最低必要字段 |
| --- | --- |
| 待发送文件 | 稳定文件标识 授权 URI 或可访问路径 名称 类型 字节大小 来源位置 |
| 传输会话 | 会话标识 协议版本 对端临时设备名 方向 状态 创建时间 |
| 传输任务 | 任务标识 所属会话 文件清单 总字节数 已确认字节数 开始结束时间 |
| 文件结果 | 所属任务 文件标识 状态 已传字节数 校验结果 接收保存位置 失败原因 |
| 接收邀请 | 临时凭证 有效期 当前会话 连接信息；不作为长期历史保存 |

原始文件是否仍存在或保存授权是否仍有效，需要在打开文件、重试等操作时重新校验。历史记录不得让已失效文件看起来仍然可正常打开。

## 9 安全性与体验要求

### 9.1 文件与会话访问

首版不设置账号。接收二维码包含建立当前临时会话所需的信息，凭证应不可预测、有有效期，并在取消、退出或会话完成后失效。只允许通过当前会话传输用户选择的文件，不能把任意路径开放为下载接口。

接收文件名需要规范化，不能利用文件名跳出授权保存目录。发送方不能自行指定接收端任意磁盘路径。短时有效期、单会话接收和接收方主动开启等待，是首版扫码连接的基本约束。

### 9.2 大文件和性能

文件内容采用流式读写，不得将完整大文件一次性读入内存。列表优先加载文件元数据，缩略图按需生成和缓存。验收应包含 1 GB 以上文件和多个不同类型文件，并记录峰值内存、网络条件和失败恢复情况。

进度需要反映对端已确认的数据，暂停、取消和错误提示应及时反馈。实际速度受设备、网络和文件大小影响，不将设计图中的速度数字写成最低性能保证。

### 9.3 页面适配与可用性

沿用 ReelBox 蓝紫配色和浅色或深色主题。顶部、底部及浮层中的按钮遵守安全区域，适配刘海、挖孔、系统手势条和横竖屏。文件名过长时允许省略展示，但需能查看完整名称，不能挤掉大小、移除按钮或下一步。

已选数量和下一步始终横向同排；弹出已选清单时该操作栏仍可用。小“×”图标需要足够触摸区域。返回操作优先收起已选抽屉或返回上级文件夹，不应直接丢弃全部选择。

## 11 实施顺序与技术决策

第一阶段完成独立导航、文件选择和已选清单，接通视频分享入口；第二阶段完成同网扫码配对、接收准备和真实文件读写；第三阶段完成进度、结果校验、取消、暂停继续和历史；最后进行大文件、权限拒绝、网络中断和反复进入退出的回归。

以下技术决策需要在实现前落定，但不应继续增加用户页面：

- 确定局域网传输协议、监听端及网络绑定方式。发送与接收是产品角色，不等同于必须由哪一方运行网络服务。
- 确认是否真的需要蓝牙或 Wi-Fi Direct。若不需要，移除对应的阻塞检查和权限请求。
- 确定接收邀请有效期、连接超时、失败重试上限和大小校验策略，并作为配置管理。
- 明确 APK 文件获取范围；已安装应用导出或拆分安装包支持需另立需求，不能用普通文件传输承诺替代。
- 首版以用户前台操作为基线；后台持续传输、锁屏保活和跨会话断点续传作为后续独立增强。
