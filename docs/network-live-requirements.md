# LumiPlayer 网络直播模块功能需求分析

文档版本：1.1  
编制日期：2026 年 11 月 12 日  
适用范围：Android 网络模块中的 B 站直播与双路观赛  
使用对象：产品设计、客户端开发、测试

本次调整让用户在网络首页选择画面、声音和弹幕来源，进入直播后再调整画质、音量和同步。首页顶部增加 B 站账号模块，未登录展示游客，登录后展示真实头像和用户名。首页保留 LumiPlayer 现有的浅色背景、白色卡片和蓝紫色主色；播放页新增统一的直播控制台，避免将所有配置堆在进入直播之前。

接收公开直播弹幕按匿名连接设计。关联 B 站账号是可选能力，用于携带平台登录态请求更高画质；实际可播放画质以接口返回为准。首版不提供发送弹幕，不要求用户注册 LumiPlayer 账号。

本文中的页面尺寸、默认值、重试次数和版本划分作为首版设计基线。本文定义待实现的行为，不表示这些能力已经接入。

## 1 产品目标与功能范围

### 1.1 核心场景

用户选择英雄联盟官方赛事直播作为画面来源，选择炫神等主播作为声音来源，并独立选择观看哪一个直播间的弹幕。播放过程中，可以切回赛事原声、调整画质、校准两路时间差；其中一路异常时，用户能知道哪一路出了问题，并进行对应恢复。

“画面来源”决定显示哪个直播间的视频。“声音来源”是可选的另一直播间；未选择时使用画面直播间原声。“弹幕来源”独立于声音选择，首版同时显示一个直播间的弹幕。

### 1.2 首版功能

| 功能 | 首版要求 |
| --- | --- |
| 查找直播 | 保留搜索主播、搜索直播间、输入房间号和粘贴链接 |
| 直播组合 | 选择画面来源、可选声音来源，保存并恢复最近一个组合 |
| 房间信息 | 区分主播头像、主播昵称、直播间标题、真实房间号与开播状态 |
| 双路播放 | 一路显示画面，一路提供声音，同时只有一路发声 |
| 接收弹幕 | 匿名初始化、连接鉴权、消息解析、显示、重连与来源切换 |
| 画质 | 根据接口返回生成选项，重新取流切换，显示实际画质与降级结果 |
| 平台登录 | 首页顶部显示游客或 B 站真实头像与用户名，提供登录、刷新状态、失效处理和退出登录 |
| 直播控制台 | 声音、音量、画质、弹幕、同步和连接恢复集中管理 |
| 收藏与开播提示 | 保留收藏，增加开播提醒订阅和应用前台检测提示 |
| 播放适配 | 支持横竖屏、安全区、屏幕亮度和系统媒体音量调节 |

### 1.3 后续功能

发送弹幕、多平台直播、多个组合的命名与管理、两路声音混音、多个画面的布局、自动语音同步、直播录制、后台音频播放和应用关闭后的开播推送放入后续版本。首版不显示这些功能的可操作占位入口。

本地播放、文件传输和网络视频直链的现有功能保持各自职责。直播控制台仅控制当前直播会话。

## 2 现有实现与调整清单

以下现状根据当前项目的网络模块代码整理。

| 现有实现 | 需要调整的内容 |
| --- | --- |
| 网络首页已有直播和视频标签、搜索、添加链接和收藏 | 保留入口，重新组织双路观赛卡片 |
| 网络首页没有账号身份展示 | 在标题下方、搜索框上方增加 B 站账号模块，区分游客与已登录用户 |
| 画面与声音来源为并排小卡片 | 改为上下两行，留出头像、昵称和标题的展示空间 |
| 已有原声与解说切换、暂停和手动同步 | 统一纳入直播控制台，补充横竖屏布局和明确状态 |
| 取流固定请求 `qn=250` | 接收画质参数，返回画质列表和实际档位，支持重新取流 |
| `LiveRoom.coverUrl` 同时承载封面或头像 | 拆分头像与封面字段，避免将直播封面作为主播头像 |
| `LivePreset` 只保存画面和声音来源 | 增加弹幕来源和必要的组合偏好，并兼容旧数据 |
| 收藏只保留开播状态布尔值 | 增加未知状态、最近检查时间和开播提醒设置 |
| HTTP 请求支持传入 Cookie，但没有平台会话管理 | 增加统一的匿名设备会话、登录态和签名服务 |
| 没有弹幕连接与渲染模块 | 新增独立弹幕会话，避免与播放连接相互阻塞 |
| 已按每次播放重新解析地址的方式取流 | 继续保留；重连也重新解析，不持久保存临时直链 |

## 3 页面结构与主要流程

### 3.1 页面与面板

| 页面或面板 | 内容与入口 |
| --- | --- |
| 网络首页 | 顶部 B 站账号模块、搜索、直播与视频切换、双路观赛、收藏 |
| 直播搜索页 | 复用现有搜索，支持选择为画面或声音来源 |
| 直播播放页 | 视频、弹幕、房间信息、基础播放操作、直播控制台 |
| 画质面板 | 展示接口返回的画质选项、当前实际画质和必要的账号入口 |
| 弹幕设置区域 | 来源、连接状态、显示样式和弹幕延迟 |
| B 站账号面板 | 登录状态、关联账号、刷新状态和退出 |
| 收藏完整列表 | 查看收藏、设为来源、开启或关闭开播提醒 |

画质、弹幕和账号采用当前页面上的面板或展开区域。用户关闭面板后继续观看，不增加一个独立的直播配置向导。

### 3.2 首次观看流程

1. 用户从网络首页搜索或粘贴链接，选择画面来源。
2. 按需选择声音来源。
3. 选择关闭弹幕、画面直播间弹幕或声音直播间弹幕。
4. 点击“进入直播”。
5. 先建立画面播放；原声可用后先正常出声，不等待可选声音源或弹幕。
6. 若用户选择了另一声音源，在其准备完成后切换过去；若用户期间主动选择了原声，则尊重最新选择。
7. 弹幕独立连接；弹幕失败时视频和声音继续播放。
8. 用户通过直播控制台调整画质、声音、弹幕与同步。

### 3.3 按需登录流程

用户可直接点击网络首页顶部游客模块中的“登录 B 站”，进入 B 站官方登录流程。登录成功且账号接口确认会话有效后，原位置更新为该账号的真实头像和用户名。

用户浏览、选源和尝试接收弹幕时不出现强制登录弹窗。用户请求更高画质而平台返回较低档位时，画质面板提示“当前可用为高清，可关联 B 站账号后重试更高画质”。“我的”中的平台账号入口作为补充入口，与首页使用同一会话状态。

取消或未完成登录时，关闭登录流程并继续当前可用播放。完成登录后刷新账号状态和可用画质，再由用户确认是否重试原先请求的档位。

## 4 网络首页设计

### 4.1 页面布局

页面从上到下依次为“网络”标题与添加链接、B 站账号模块、搜索框、直播与视频标签、双路观赛卡片和我的收藏。账号模块位于标题下方、搜索框上方，直播与视频标签切换时均保留。页面左右间距以 16 dp 为基准，卡片内边距为 14 至 16 dp，双路观赛卡片与收藏标题间距以 16 dp 为基准。

沿用用户确认的原有整体风格，不采用 FreeCast 的 A/B 开关布局。卡片高度由内容决定，不通过大块留白撑高页面。

### 4.2 顶部 B 站账号模块

账号模块采用与页面一致的浅色卡片，基础高度为 72 dp 左右，左右内容横向排列，随文字缩放允许增高。头像尺寸建议为 40 dp，不使用大面积登录横幅。模块与搜索框的间距以 12 dp 为基准。

未登录时使用统一默认头像，主文字显示“游客”，辅助文字显示“登录后可尝试更高画质”，右侧为“登录 B 站”按钮。点击默认头像、文字区域或登录按钮均进入同一个登录流程。

登录后，同一位置替换为平台返回的真实头像和用户名，辅助文字显示“B站账号 · 已登录”，右侧显示“管理”入口。用户名最多一行，长名称省略，完整名称可在账号面板查看；头像下载失败时使用占位图，用户名和有效登录态仍然保留。

```text
未登录
┌──────────────────────────────────────────┐
│ [默认头像] 游客                 登录 B站 │
│            登录后可尝试更高画质           │
└──────────────────────────────────────────┘

已登录
┌──────────────────────────────────────────┐
│ [真实头像] 平台用户名             管理 › │
│            B站账号 · 已登录               │
└──────────────────────────────────────────┘
```

点击已登录的头像、用户名或管理入口，打开账号面板，展示头像、完整用户名、UID，以及刷新状态、切换账号和退出登录操作。登录成功后自动关闭登录流程并更新当前页面，不要求重启应用或手动刷新。

账号模块的加载、失效和网络失败表现见第 9 节。游客依然可以选源、观看平台允许的直播和接收弹幕，不通过账号卡阻断这些操作。

### 4.3 来源条目

每个来源使用一行完整信息区域，头像尺寸建议为 44 至 48 dp。昵称、直播标题分开显示；名称较长时省略，不挤占“更换”按钮。点头像或房间信息可查看完整名称、标题和房间号，点“更换”进入选源。

画面来源必选，空状态显示“选择赛事或直播画面”。声音来源可选，空状态显示“选择解说声音，可先听原声”；已选声音来源提供清除入口。

状态分为直播中、未开播和状态待更新。上次搜索得到的状态只是快照；进入直播前重新检查。刷新失败显示“状态暂不可用”，不能将网络失败写成“未开播”。

### 4.4 弹幕来源

采用“关闭／画面直播间／声音直播间”三段选择。首次使用默认为关闭，保存组合时记住选择。选择声音直播间前必须已设置声音来源；未设置时该项不可选，并提供清晰提示。

下方只用一行说明当前来源，例如“当前弹幕：炫神_”。首页不展开字号、透明度、音量、画质和同步参数。

清除声音来源时，如果弹幕也选择了该来源，弹幕改为关闭并提示“声音来源已移除，弹幕已关闭”。画面与声音实际属于同一个房间时，按真实房间号去重，不重复建立连接。

### 4.5 进入与保存

没有画面来源时，主按钮显示“选择画面来源”并进入选源。已选择时显示“进入直播”；明确未开播时提供刷新状态的操作，状态未知时允许重新检查并尝试进入。

声音源未开播时显示“声音源未开播，进入后先听原声”。不阻止观看画面，不删除原有声音选择。

“保存组合”保存最近一个画面、声音及弹幕来源组合。返回首页时保留尚未保存的本次选择；冷启动优先恢复已保存组合。不要把刷新状态失败当作清空组合的理由。

### 4.6 收藏与开播入口

收藏条目展示头像或封面、昵称、直播标题、开播状态和铃铛。铃铛表示开播提醒订阅，星标表示收藏，两者状态独立。

完整列表支持设为画面来源、设为声音来源、取消收藏和切换开播提醒。未收藏的来源也可订阅开播提醒；订阅按真实房间号保存，不因来源被替换而自动删除。

## 5 播放页与直播控制台

### 5.1 竖屏布局

竖屏上方展示视频，默认保持 16 比 9 的播放区域；实际画面采用等比包含方式，避免裁掉赛事比分等信息。下方显示当前房间信息和直播控制台。小屏设备允许控制台纵向滚动，视频区域与返回操作保持可访问。

```text
返回                         直播间名称
┌──────────────────────────────────┐
│ 视频画面与弹幕                    │
│                                  │
│ 播放/暂停  实际画质  弹幕  全屏   │
└──────────────────────────────────┘
[头像] 画面：赛事官方
[头像] 声音：炫神_          当前使用：解说声音

直播控制台
声音    [画面原声 | 解说声音]    静音
音量    ─────────●──────          65%
画质    高清                     选择 ›
弹幕    声音直播间 · 已连接       设置 ›
同步    画面延迟 0.0s · 声音延迟 0.0s  展开
连接    画面正常 · 声音正常       更多 ›
```

“画面原声”在赛事场景可以展示为“赛事原声”。解说选项显示选定主播的名称，避免用户选择多个主播后仍只看到含义不明确的“解说”。

### 5.2 横屏布局

横屏以视频为主，单击显示顶部信息和底部工具条，4 秒无操作后隐藏。弹幕不会随工具条隐藏。底部优先展示播放、声音来源、弹幕开关、实际画质和控制台入口；宽度不足时将次要操作收入控制台，不能压缩成难以点击的小按钮。

控制台从右侧滑出，内容与竖屏一致，面板宽度取屏幕宽度约 42%，并限制在 280 至 400 dp；可用空间不足时使用更宽面板和内部滚动。点击画面遮罩、关闭按钮或系统返回先关闭面板。

横竖屏切换复用同一直播会话。弹幕连接、当前声音、系统音量、实际画质和同步偏移不得因重新布局而重置。

### 5.3 声音控制

首版提供画面原声与所选解说声音二选一，不提供混音及两套音量滑块。切换时先静音旧声道，再打开目标声道，确保不会同时出声。

控制台只提供一个系统媒体音量滑块，与右侧上下滑动手势和手机音量键保持一致。播放器路由所需的内部增益与系统音量分开管理；切换来源、重连和画质切换不得把用户音量重新设到固定值。

静音按钮只静音本次播放器输出，保留系统媒体音量。切源后维持静音状态；取消静音后使用当前系统音量，不强制恢复到 100%。

解说断开时，回退画面原声并显示“解说连接中断，已切回原声”，同时保留解说选择供重试。用户已主动选择原声时，解说恢复不能抢占当前声音。

### 5.4 画质与弹幕入口

工具条上的画质文字表示正在播放的实际画质。点画质打开选项面板；画质切换期间显示“正在切换”，成功后再更新选中状态。

弹幕图标用于快速显示或隐藏当前选定来源的弹幕，控制台中的“设置”用于更换来源和调整样式。关闭后记住上次非关闭来源；没有历史来源时，首次打开默认选择画面直播间并显示来源说明。

### 5.5 连接与错误信息

控制台分别展示画面、声音和弹幕状态，提供重试画面、重试声音、重连弹幕以及重新连接全部的操作。只有画面失败且无法观看时，才展示覆盖视频的主错误状态。

常规界面使用中文短提示，不直接显示完整 CDN 地址、Cookie 或弹幕 token。“错误详情”可以展示阶段、HTTP 状态码和简短原因，复制诊断时去除临时地址的签名参数及账号凭证。

### 5.6 手势与安全区

左侧上下滑动调整本次播放的屏幕亮度，右侧上下滑动调整系统媒体音量。手势开始时读取实际值，滑动期间使用本次手势累计值，结束后核对平台结果，避免系统异步回调让数值反复跳回初始值。

控制台、弹层和按钮区域优先响应自己的操作，不触发底层播放手势。直播首版不启用点播的横向快进、快退和长按倍速；有缓存也不显示一个不可用的点播总时长或进度条。

可交互控件根据系统安全区与横屏刘海区域动态布局，视频背景可延伸至屏幕边缘。按钮不能依赖固定距离躲避摄像头；在打孔屏、刘海屏、手势导航和三键导航下均需验收。

### 5.7 播放中更换来源

点控制台中的画面或声音信息可更换对应来源，复用已有的搜索和收藏选择能力。进入选择和取消选择均保留当前会话；确认新来源后再提交变更。

未施加同步偏移时，更换声音只重建声音一路，画面继续播放；新声音不可用时保留画面原声并说明原因。已有同步偏移时，更换任意来源都需要重连两路，使偏移确实归零。更换画面先检查新房间状态，确认可尝试播放后重建直播会话，并保留另一声音来源的选择。无法建立新画面时提供返回上一房间的操作。

弹幕来源按“画面直播间”或“声音直播间”的角色跟随新房间，重新取凭证并清空旧消息。换源清零本次同步和弹幕延迟；在确认操作处简短提示，不能保留一个看似有效的旧偏移数值。

## 6 双路连接与恢复要求

### 6.1 启动与资源

画面来源必须成功才算进入可观看状态。可选声音来源在独立任务中准备，弹幕连接也独立进行。画面准备好后先使用可用原声，不能因为声音或弹幕失败而一直显示整体加载。

声音播放器不创建视频渲染控制器，并关闭视频轨。只有接口实际提供纯音频地址时才将其标为纯音频传输；否则不承诺关闭视频轨就能消除视频数据的网络开销。

同一真实房间同时用作画面和声音时，复用画面播放器的原声。稳定播放时只有一路画面播放器和至多一路额外声音播放器。

### 6.2 线路与超时

每次进入、重连或切画质时重新获取临时播放地址，按服务返回的有效候选线路尝试。单路启动的总超时为 45 秒，最多尝试 3 条候选线路；单条连接等待首帧或有效音频不超过 20 秒，且必须受剩余总时间约束。

画面以实际首帧判断可观看，声音以有效音轨和播放进度判断可用，不以直播总时长大于零作为成功条件。失败后提供可执行的重试入口，不能无限转圈。

连接失败需区分未开播、地址不可用、网络超时、平台验证和播放器失败。HTTP 403 或地址打开失败时先重新解析一次，不能仅凭 403 就认定一定是未登录。

### 6.3 暂停与生命周期

暂停时固定当前画面并停止两路出声。首版将继续操作定义为回到当前可用直播位置：重新建立直播连接，清空本次同步偏移和旧弹幕队列，并显示“已回到直播”。界面说明“继续将回到直播”，不承诺无限期保留暂停位置。

退出播放页或应用进入后台时停止本次两路播放、弹幕心跳及自动重试，并释放播放器；首版不保持后台音频。回到同一播放页后保留用户选源和样式偏好，重新连接直播，不复用已经失效的 URL 或 token。

连续点击重试、快速切源、退出后重新进入，都必须使旧任务失效。旧请求完成后不得覆盖新房间、重新挂载已退出播放器或重启已关闭弹幕。

### 6.4 播放中的连接中断

声音中断时立即回退原声，允许重新解析并自动恢复一次，恢复过程受单路 45 秒预算约束；失败后等待用户重试。画面中断时暂停当前解说输出，避免画面错误覆盖层下仍单独播放解说，并自动重新解析恢复一次。

画面恢复后按照用户最新的声音选择恢复出声。无论恢复哪一路，若之前存在同步偏移，都需要刷新两路连接、清零偏移并提示重新校准，使显示的零偏移与实际连接状态一致。网络恢复事件只启动一轮有效恢复任务。

## 7 弹幕功能需求

### 7.1 匿名连接

匿名连接不以 B 站已登录作为前置条件。平台适配层完成以下步骤，并在已有登录会话时自然携带有效会话，不另建一套弹幕账号：

1. 初始化或复用平台签发的匿名设备标识 `buvid3`。
2. 请求网页导航接口，取得当前 WBI 公共签名信息。
3. 对 `getDanmuInfo` 请求签名，获取当前房间 token 与服务地址。
4. 连接平台返回的 WebSocket 服务器，使用房间号、设备标识、token 和用户 ID 鉴权；匿名用户 ID 使用 `0`。
5. 鉴权成功后开始接收和展示消息，维持心跳并处理断线。

平台设备标识由设备初始化流程取得，不能将随机字符串等同于平台初始化完成。设备标识、Cookie、签名和 WebSocket 凭证属于不同环节，不能只填一个参数就将状态标为“弹幕已连接”。

### 7.2 消息与显示

首版显示普通文字弹幕，支持平台协议中的分包、连续数据包和所选压缩格式。未知消息类型跳过，错误数据包不能导致播放器退出。礼物、舰长、付费留言、表情贴图和发送弹幕暂不纳入首版展示。

弹幕层显示在视频有效画面范围内，并避开控制条和安全区。首版提供字号小中大、透明度 30% 至 100%、显示区域四分之一／二分之一／全屏、密度低中高。初始值为中字号、80% 透明度、上半屏、中密度。

按可用轨道调度滚动文字，同轨道避免明显重叠。持续高峰时丢弃超出显示能力的旧消息，待显示队列上限为 200 条，不通过无限累积追赶历史弹幕。

### 7.3 来源切换与隐藏

关闭、画面直播间、声音直播间的选择与首页语义一致。切换时立即停止旧房间的连接、心跳和显示队列，再为新房间取凭证，不能混入旧房间消息。切换声音输出不会自动改变弹幕来源。

隐藏弹幕时关闭连接并清空显示队列，记住最近的非关闭来源；再次打开时建立新连接，只显示新收到的消息。横竖屏切换只迁移显示层，不重复建连。

所选房间未开播时显示“该直播间未开播，弹幕暂不可用”。不得静默替换成另一个房间的弹幕。声音回退原声也不改变用户选择的弹幕来源。

### 7.4 弹幕延迟

设置中提供本次会话的弹幕延迟，范围为 0 至 30 秒，步长 0.5 秒，默认 0。它用于用户手动补偿直播画面与弹幕到达时间的差异，不表示已经自动测出两个直播间的真实时间差。

增大延迟只影响之后的排队与显示，不重播已显示消息；减小延迟时丢弃过时队列，避免瞬间刷屏。更换来源、重连、回到直播或切画质导致重建会话时清空队列并归零；字号等显示偏好继续保留。

### 7.5 心跳与失败恢复

以 FreeCast 参考实现的 25 秒心跳、70 秒无有效响应超时作为接入初始值，鉴权超时为 15 秒；联调时根据实际协议调整。普通断线按 2、4、8、16、30 秒退避，连续 5 次恢复失败后停止自动重试，展示“重连弹幕”。

出现平台验证类错误，例如 `-352`、`-403` 或 HTTP 412 时，停止当前自动重试链，提示“B 站要求验证，请完成验证后重连”。不要将所有校验失败统一提示成“请先登录”，也不要通过持续请求掩盖失败。

弹幕失败只更新弹幕区域，不暂停、重建或静音视频和声音。

## 8 画质功能需求

### 8.1 画质选项

取流方法接收用户请求的画质参数，不再固定 `qn=250`。优先使用平台返回的画质名称，通过 `g_qn_desc` 与 `accept_qn` 组织可尝试的选项，通过实际地址所属的 `current_qn` 确认播放档位。

列表中出现某个档位不表示当前账号一定有权得到对应地址。档位编号也不直接等于固定像素分辨率；界面不能仅凭 `qn` 宣称已播放 1080P、2K 或 4K。

首次进入时尝试平台的原画档位，遇到降级后继续使用实际可用画质。用户选择过其他档位后，记录为偏好；每次进入仍重新解析，并以实际结果显示。

### 8.2 切换与失败回退

切换时显示请求档位和切换状态，成功后显示实际档位。较低档位成功返回时视为可用播放，提示“当前返回高清，未获取到原画”，不能显示原画选中但实际播放高清。

切换失败时，用之前成功播放的画质参数重新取流恢复，不反复打开旧直链。恢复失败才进入画面错误状态。弹幕自身的故障不触发画质回退。

无手动同步偏移时，可以只重建画面一路并保持解说音频；存在偏移时，切画质按双路重连处理，先提示“切换后需重新校准”，完成后清零两路同步偏移。重建期间维持用户的声音选择、音量和静音偏好。

### 8.3 登录与实际权限

匿名请求被降级时提供“关联 B 站账号后重试”入口，不能保证登录一定获得最高档位。已登录仍被降级时提示“平台未返回所选画质，已使用当前可用画质”，同时提供刷新账号状态和重试。

用户取消登录时继续当前播放，不反复弹窗。只为画面一路提供画质菜单；声音来源首版不展示一个没有实际用途的视频画质选择器。

## 9 B 站账号与会话需求

### 9.1 入口与状态

网络首页顶部账号模块为主入口，“我的”中的平台账号和画质受限提示为补充入口。所有入口共享同一份 B 站会话和账号信息，不分别保存互相矛盾的登录标记。

状态包括检查中、游客、登录中、已登录、登录失效、需要平台验证和状态检查失败。顶部模块按下表展示：

| 账号状态 | 顶部模块内容 | 主要操作 |
| --- | --- | --- |
| 没有有效登录会话 | 默认头像、游客、登录后可尝试更高画质 | 登录 B 站 |
| 正在恢复或检查已有会话 | 最近已验证的账号资料，辅助文字为正在检查；没有资料时用检查中的占位 | 合并重复检查，不重复打开登录流程 |
| 登录进行中 | 保留游客或现有账号资料，提示正在登录 | 返回、取消或等待平台认证结果 |
| 已登录 | 平台头像、真实用户名、B站账号与已登录状态 | 管理账号 |
| 平台明确返回未登录或会话失效 | 默认头像、游客，辅助文字为 B站登录已失效 | 重新登录 |
| 状态检查因网络失败 | 有历史资料时保留并标记暂未验证，无资料时展示游客与检查失败说明 | 重试检查；不反复弹出登录页 |
| 平台要求额外验证 | 保留必要资料，说明需要完成 B 站验证，不将其标为登录成功 | 完成验证后刷新 |

网络请求失败不能直接判定退出登录，头像加载失败也不能改变账号身份。只有平台明确确认登录失效或用户退出时，才将原有效账号切为游客。匿名设备会话与登录会话分开管理，不把存在 `buvid3` 当作已经登录。

### 9.2 Flutter 登录接入前置验证

FreeCast 公开的浏览器扩展通过打开 B 站官网、复用浏览器 Cookie 完成关联。Flutter 的 `HttpClient` 不会自动取得用户在系统浏览器或 B 站 App 中的登录态，不能照搬浏览器扩展的 Cookie API。

开发顺序必须先完成登录接入验证：优先验证在受控 WebView 中打开平台官方登录页面，并确认登录结果可用于本应用的取流请求；平台限制导致不可行时，再评估平台提供的扫码登录流程。二维码方案若采用，需独立验证申请、状态查询、过期和取消流程。

验证的完成标准是同一测试账号的登录状态可识别、登录前后取流请求携带正确会话、退出后凭证确实移除。验证不以“登录页面显示成功”或“取到最高画质”单独作为标准。最终交互只采用验证通过的一种主方案，不要求用户手动粘贴 Cookie。

### 9.3 登录接口与账号资料同步

账号认证使用 B 站官方登录流程及其对应接口，取得可供本应用后续请求使用的登录会话，不增加 LumiPlayer 自建账号注册流程。登录组件必须覆盖开始登录、取消、认证成功、失败和会话过期；采用扫码方案时，还需覆盖等待扫码、等待确认和二维码过期。

登录成功回调后，请求账号状态与资料接口，确认登录有效并取得 UID、用户名和头像地址，再同时更新顶部身份信息及会话状态。`/x/web-interface/nav` 用于检查账号状态和读取账号资料，不把它当作签发登录凭证的登录接口；具体返回字段由平台适配层统一转换为账号摘要。

顶部信息不使用假用户名或固定头像模拟登录成功。资料缺失时显示明确的账号资料加载状态，并允许重试；头像图片请求失败可使用占位图，不能混用上一个账号的头像、名称和新账号的会话。

首次恢复已保存会话、用户登录完成、切换账号、回到前台及主动刷新时检查账号资料。并发检查合并为同一任务，旧账号的迟到结果不得覆盖新账号。状态确认前不把缓存资料当作当前平台权限的证明。

从首页启动登录，成功或取消后返回原页面，保留已选择的画面、声音和弹幕来源。成功后刷新画质能力，但不自动开始播放，也不自动改变正在观看的画质。

### 9.4 会话保存与变更

登录凭证保存在受系统保护的凭证存储中，普通网络数据表只保存必要的展示信息和用户偏好。Cookie 仅发给适用的平台域名，不能将登录 Cookie 全局附加到任意 CDN 或用户输入的 URL。

账号切换或退出后取消旧账号发起的待完成鉴权任务，清除旧弹幕 token，并按当前账号或匿名身份重新建立后续请求。退出后顶部立即恢复默认头像和“游客”；切换成功后替换为新账号头像与用户名。保留收藏和选源组合；退出后当前直播降级为匿名可用播放，不承诺继续保持原来受限画质。

## 10 双路同步需求

### 10.1 操作语义

控制台的同步区域默认折叠，展开后显示两路已施加的本地延迟和以下操作：

| 操作 | 用户遇到的情况 | 实际行为 |
| --- | --- | --- |
| 画面慢 0.5 秒 | 解说比画面晚，先看到动作后听到解说 | 将画面一路再延迟 0.5 秒 |
| 声音慢 0.5 秒 | 解说比画面早，先听到解说后看到动作 | 将声音一路再延迟 0.5 秒 |
| 回到直播并重置同步 | 希望清除累计延迟或重新校准 | 重新取流、重连两路并清零偏移 |

首版每次增加 0.5 秒，每侧累计上限 30 秒。只有双路均稳定播放时才能调整；单路原声播放时显示“选择并连接另一声音源后可调整双路同步”。

### 10.2 状态与限制

延迟通过播放器有效缓存实现，只能增加已有延迟，不能将尚未到达的直播内容提前播放。操作期间显示“正在调整”，暂时禁用同类按钮；缓存不足或参考路未推进时明确失败，不增加界面计数。

两路时间差由用户判断。播放器读到的两路 position 不直接代表同一个真实比赛时刻，首版不显示未经测量的“已精确同步”状态。

同步偏移只在本次连接内有效。换源、重新连接、回到直播和需要重建双路的画质切换后清零，不将旧数字写回新流。两个主播本身转播不同内容时，同步功能不承诺解决内容差异。

## 11 开播提示需求

### 11.1 首版提示范围

首版提供应用前台运行期间的开播检测和应用内提示，不承诺应用关闭后的实时推送。铃铛旁或首次启用提示中说明“应用使用期间提醒”。不因该功能预先申请通知权限。

应用在前台时，每 60 秒检查已订阅房间；页面进入、手动刷新和回到前台可以触发一次检查，相同房间 30 秒内合并请求。每次最多 4 个并发检查；后台和进程退出后停止轮询。

以后若需要应用关闭后的推送，需另行设计后台检测与通知投递能力，并根据采用的机制申请所需系统权限，不能只增加一个通知开关就宣称已经实现。

### 11.2 提示规则

订阅以真实房间号去重。首次检查发现已在直播时展示“当前正在直播”，不伪装成刚开播；已确认未开播后检测到直播中，触发一次“主播已开播”提示，并可点击进入该房间。

同一轮持续直播只提醒一次。只有再次可靠观察到未开播后才允许下一次提醒。网络失败保持未知或上次状态，不将错误当作下播，不反复制造开播事件。

观看期间收到其他主播开播提示，仅展示轻提示，不自动替换当前来源、暂停播放或切走页面。

## 12 状态与异常处理

### 12.1 独立状态

| 对象 | 至少需要区分的状态 |
| --- | --- |
| 房间 | 未知、检查中、直播中、未开播、检查失败 |
| 画面 | 未连接、解析中、连接中、可播放、切换中、失败、已关闭 |
| 声音 | 未选择、连接中、可用、正在使用、失败、回退原声 |
| 弹幕 | 已关闭、取凭证中、连接中、已连接、等待重试、需要验证、失败 |
| 账号 | 检查中、未关联、已关联、失效、需要验证、检查失败 |
| 同步 | 可调整、调整中、缓存不足、达到上限、需要重新校准 |

用户希望使用的来源、当前实际播放来源和失败原因分别保存。一个全局状态字符串可以用于摘要，但不能成为这些独立状态的唯一来源。

### 12.2 异常处理表

| 异常 | 页面表现 | 恢复操作 |
| --- | --- | --- |
| 画面未开播 | 显示房间信息与未开播状态 | 刷新状态或开启开播提醒 |
| 声音未开播或失败 | 保持画面，使用原声并说明原因 | 重试声音或更换声音来源 |
| 弹幕鉴权失败 | 弹幕区域显示失败，播放继续 | 完成必要验证后重连弹幕 |
| 请求高画质被降级 | 保持可用画面，标明实际档位 | 关联账号、刷新状态或重新选择 |
| 账号过期 | 显示需要重新关联 | 保持匿名可用能力，按需重新关联 |
| 临时直播地址失效 | 显示重新解析与连接状态 | 获取新地址，候选线路失败后展示错误 |
| 网络整体断开 | 各受影响组件展示网络异常 | 网络恢复后重新取流，旧任务不得重复恢复 |
| 同步缓存不足 | 当前播放继续，偏移数字不变 | 重新稳定播放后调整或回到直播 |
| 用户退出或快速换源 | 旧操作立即失效 | 只允许最新会话更新页面 |

## 13 数据与持久化需求

| 数据对象 | 新增或明确的字段 | 保存规则 |
| --- | --- | --- |
| 直播间 | 平台、真实房间号、短号、主播 UID、昵称、头像、标题、封面、状态、检查时间 | 保存稳定身份和最近展示快照 |
| 组合 | 画面房间、可选声音房间、弹幕来源枚举 | 保存最近一个明确保存的组合 |
| 播放偏好 | 请求画质、弹幕字号、透明度、区域、密度、上次非关闭弹幕来源 | 保存用户偏好，不冒充当前实际状态 |
| 画质结果 | 可尝试档位、请求档位、实际档位、当前候选线路 | 仅当前会话有效 |
| 播放状态 | 期望声音来源、实际声音来源、静音、各路状态、错误、会话版本 | 仅当前会话有效 |
| 弹幕连接 | 房间、服务器、token、鉴权状态、重试次数、待显示队列 | 临时内存状态，退出后清理 |
| 平台会话 | 匿名设备信息、登录凭证、UID、用户名、头像地址、最近确认时间、账号状态、签名信息 | 凭证与普通数据分开；资料缓存标明验证状态；签名信息按有效性刷新 |
| 开播提醒 | 真实房间号、订阅状态、上次可靠状态、当前直播是否提醒过 | 持久保存，支持去重 |
| 同步偏移 | 画面延迟、声音延迟、弹幕延迟 | 仅本次连接有效，不跨重连恢复 |

旧数据升级时，原有收藏、画面来源和声音来源继续可读。旧组合没有弹幕字段时按关闭处理；旧 `coverUrl` 无法确定是头像时，先作为封面保留，并重新拉取头像，避免直接批量复制为头像。

## 14 技术拆分与接口契约

### 14.1 模块职责

保留当前网络模块的分层结构，新增组件使用独立职责，名称可在开发时调整。

| 组件 | 职责 |
| --- | --- |
| `BiliLiveApi` | 搜索、房间资料、开播检查、按画质取流；返回结构化结果 |
| `BiliSessionService` | 匿名设备初始化、平台登录接口交互、账号资料与状态同步、Cookie 作用域和退出 |
| `BiliWbiSigner` | 获取和缓存签名信息，对需要签名的请求生成参数 |
| `BiliDanmakuClient` | 连接凭证、WebSocket 协议、解压、心跳和重试 |
| `DanmakuController` | 来源选择、显示队列、轨道调度、延迟和样式 |
| `DualLiveSession` | 两路播放、声音路由、独立重连、画质切换和同步 |
| 播放页状态控制器 | 汇总页面可观察状态，区分用户意图和实际结果 |
| `LiveReminderService` | 前台检测、订阅与事件去重 |
| `NetworkRepository` | 收藏、组合、偏好和旧数据迁移，不存临时流地址 |

### 14.2 接口契约

取流结果至少包含真实房间号、请求画质、可尝试画质列表、带实际画质的候选地址和打开流所需请求头。房间是否开播、网络错误与平台校验失败需使用不同结果或异常类型。

弹幕凭证结果至少包含真实房间号、WebSocket 服务器候选、token、用户 ID 和设备标识；凭证只在内存中交给弹幕连接组件。消息解析后的领域事件不暴露登录 Cookie。

所有异步操作携带当前会话版本；页面关闭、换源或账号切换后，旧版本的结果一律忽略。播放、弹幕和账号检查不共用会造成互相等待的一条操作队列；确实影响同一播放器的操作需要串行化。

### 14.3 平台网页接口

以下路径用于明确参考实现的接入位置，属于 B 站网页接口链路。联调需要核对当前实际返回字段，不能将路径存在等同于永久可用。

| 目的 | 参考接口 |
| --- | --- |
| 匿名设备初始化 | `api.bilibili.com/x/frontend/finger/spi` |
| 登录认证 | 接入验证通过的 B 站官方登录流程及对应接口，负责取得本应用可用会话；与状态查询接口分开 |
| 账号状态与 WBI 信息 | `api.bilibili.com/x/web-interface/nav` |
| 短号转真实房间及开播状态 | `api.live.bilibili.com/room/v1/Room/room_init` |
| 房间资料 | `api.live.bilibili.com/room/v1/Room/get_info` 等资料接口，头像来源另行核对 |
| 按画质取流 | `api.live.bilibili.com/xlive/web-room/v2/index/getRoomPlayInfo` |
| 弹幕连接凭证 | `api.live.bilibili.com/xlive/web-room/v1/index/getDanmuInfo`，按需 WBI 签名 |
| 弹幕长连接 | 凭证接口返回的 WebSocket 地址及 `/sub` 路径 |

本期接收弹幕不调用发送接口，不涉及投稿、关注、送礼或其他账号写操作。

### 15.1 首页与控制台
