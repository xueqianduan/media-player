# LumiPlayer 核心功能学习打卡

这份计划适合已经能读懂 Dart 代码、正在学习 Flutter 项目组织方式的人。每天花 30 到 45 分钟，从一个用户操作出发，找到处理它的代码、状态变化和最终结果。完成 12 天后，试着独立定位一个之前没读过的功能。

播放控制只完整跟一次「播放／暂停」。倍速和其他控制项遇到时认出入口即可。播放队列单独读一次自动换片，重点是下一条视频怎么选。字幕与音轨选字幕作为代表，直播控制台重点看画面和声音如何协作。

每天先按界面入口操作一遍，再用 IDE 的「转到定义」跟着方法走。能运行时可以下断点观察状态。直播间未开播或手头只有一台设备时，可以先画调用顺序，把真机验证记到当天笔记里。想查目录职责时再翻[项目结构](PROJECT_STRUCTURE.md)。

## 第 1 天 设置开关与 Riverpod

**入口**　我的 → 播放设置 → 播放时保持屏幕常亮。

- [ ] 找到开关的 `value` 和 `onChanged`。对照 `ref.watch(settingsControllerProvider)` 和 `ref.read(settingsControllerProvider.notifier)`，分别找到页面订阅的 `AppSettings` 和处理操作的 `SettingsController`。 [设置页面](../lib/features/settings/presentation/settings_pages.dart)
- [ ] 从 `setKeepScreenOn` 跟到 `_update`，看 `state` 何时替换、Repository 何时保存。再找启动时的 `load()` 和播放器的 `_syncWakelock`，把「更新界面」「重启恢复」「实际生效」标在三个不同的方法旁。 [Controller](../lib/features/settings/application/settings_controller.dart) · [设置仓储](../lib/features/settings/data/settings_repository.dart) · [启动流程](../lib/app/bootstrap.dart) · [播放器](../lib/features/player/presentation/player_page.dart)

**打卡题**　拨完开关后，哪个赋值让页面拿到新设置？重新打开 App 时，初始值从哪里来？

## 第 2 天 扫描相册并更新视频库

**入口**　本地页 → 重新扫描视频。

- [ ] 从本地页跟到 `LibraryController.scan`。沿着「开始扫描 → 回传进度 → 合并结果」读一遍，再看权限不足时页面用哪条消息。 [本地页](../lib/features/library/presentation/local_page.dart) · [媒体库 Controller](../lib/features/library/application/library_controller.dart)
- [ ] 看 `PhotoManagerMediaScanner` 如何收集相簿和视频，再读 `LibraryRepository.mergeScan`。挑一个已有 `sourceId` 的视频，确认重新扫描时哪些信息来自系统，哪些用户信息会保留。 [扫描器](../lib/features/library/data/media_scanner.dart) · [视频库仓储](../lib/features/library/data/library_repository.dart)

**打卡题**　扫描器交回了什么？为什么还要把结果与旧视频库合并？

## 第 3 天 从点击视频到开始播放

**入口**　本地视频列表 → 点击一个视频 → 暂停一次。

- [ ] 从 `openPlayer` 看 `/player` 路由收到的 `PlayerArgs`，记下列表传了哪些数据。到 `PlayerPage` 看它如何创建 `PlaybackSession`，再跟 `start` 到 `_openCurrent`，找到解析播放源和调用 `engine.open` 的地方。 [播放入口](../lib/features/library/presentation/video_actions.dart) · [路由](../lib/app/router.dart) · [播放器](../lib/features/player/presentation/player_page.dart) · [播放会话](../lib/features/player/domain/playback_session.dart)
- [ ] 只追一次 `_togglePlay`，看 `PlaybackSession` 如何判断暂停还是播放，`MediaKitPlaybackEngine` 如何把指令交给插件，以及插件的 `playingStream` 如何更新会话状态。Session 在这里管理一次播放过程里的状态和操作。 [引擎接口](../lib/features/player/domain/playback_engine.dart) · [MediaKit 实现](../lib/features/player/data/media_kit_engine.dart)

**打卡题**　视频列表交给播放器的是视频 ID 还是文件路径？真正打开视频之前，哪一步拿到了可播放地址？

## 第 4 天 播放进度保存与断点续播

- [ ] 从暂停分支找到 `PlaybackSession.saveProgress`，顺着 `PlayerPage` 创建 Session 时传入的回调，追到 `LibraryController.saveProgress` 和仓储的 `updateProgress`，找到进度记录按什么键保存。 [播放会话](../lib/features/player/domain/playback_session.dart) · [播放器](../lib/features/player/presentation/player_page.dart) · [媒体库 Controller](../lib/features/library/application/library_controller.dart) · [视频库仓储](../lib/features/library/data/library_repository.dart)
- [ ] 在 `_prepareAndStart` 里找到读取历史进度和计算 `startAt` 的代码。对照 `PlaybackProgress.shouldResume`，用暂停保存的单元测试检查自己对写入链路的理解。 [进度模型](../lib/features/library/domain/models.dart) · [播放会话测试](../test/unit/playback_session_test.dart)

**打卡题**　暂停时谁写进度？重新打开时谁决定从第几秒开始？

## 第 5 天 播放列表与自动换片

**入口**　打开一个至少有两条视频的播放列表 → 选列表循环 → 从最后一条开始，等它自然播完。

- [ ] 在播放列表详情找到传给 `openPlayer` 的视频顺序和起始下标，再对照 `PlaybackQueue` 保存的当前项。记下列表数据如何变成这一次播放的队列。 [播放列表详情](../lib/features/playlist/presentation/playlist_detail_page.dart) · [播放队列](../lib/features/player/domain/playback_queue.dart)
- [ ] 从 `PlaybackSession._handleCompleted` 跟到 `queue.next(auto: true)`。只看列表循环到末尾这一支，先预测队列的返回值，再用「列表循环从末尾回到开头」的单元测试核对。 [播放会话](../lib/features/player/domain/playback_session.dart) · [队列测试](../test/unit/playback_queue_test.dart)

**打卡题**　最后一条播完时，谁决定下一条是谁？谁负责打开它？

## 第 6 天 内嵌字幕与异步状态

- [ ] 找到 `selectSubtitleTrack` 的界面入口，跟到 Session 的 `_changeSubtitle` 和引擎的同名方法。把 UI 眼里的轨道 ID 和引擎执行的轨道切换对应起来。 [播放器](../lib/features/player/presentation/player_page.dart) · [播放会话](../lib/features/player/domain/playback_session.dart) · [MediaKit 实现](../lib/features/player/data/media_kit_engine.dart)

**打卡题**　旧视频的字幕切换结果晚回来时，哪一个判断保护了新视频的字幕状态？
